### Lean pattern worth remembering (block endpoint arithmetic)

`linarith`/`nlinarith` in this environment treat `↑q / 2` as an *opaque atom*
and cannot relate it to `↑q`, and `omega` fails on `k*q` (a product of two
variables is not linear). The robust pattern for `blockLeft`-style statements:

1. state the integer hypothesis in **doubled** form (`4jq + q < 2d`),
2. `have hcast : ((4*j*q + q : ℕ) : ℝ) < ((2*d : ℕ) : ℝ) := by exact_mod_cast h`,
   then `push_cast at hcast`,
3. prove a `key` identity putting `/2` on the whole expression
   (`2*j*q + q/2 = (4*j*q + q)/2` by `ring`),
4. `rw [key, div_lt_iff₀ (by norm_num : (0:ℝ) < 2)]` (or `le_div_iff₀`),
5. `linarith`.

Reverse direction (real interval → integer spacing) is easier: `push_cast`
then `linarith`, then `exact_mod_cast`. Do NOT try to obtain `q ≥ 1` from
`1 ≤ k` alone — it needs `q ≥ 1` explicitly (the target supplies `4 ≤ q`).

Also note: `Nat.lt_div_add_one_mul_self` does NOT exist here; use
`Nat.div_lt_iff_lt_mul` (with `0 < m`) to get the strict upper bound.

### KEY discovery: the node's envelope is at HALF Tao's frequency

The node's envelope is `|sin (π · (2α) · d)|`; Tao's (5.16) bounds
`1/|sin (π · 4dα)| ≤ q`. Since `π·4dα = 2·(π·2dα)`, the double-angle identity
`sin 2u = 2 sin u cos u` gives `|sin 2u| ≤ 2|sin u|`, hence
`1/|sin u| ≤ 2/|sin 2u| ≤ 2q`. **This factor of two is precisely Tao's `2q`.**
The transfer must handle `sin(2u) = 0` separately: then `|sin u| ∈ {0,1}`
(from `sin²+cos²=1`), so `1/|sin u| ≤ 1 ≤ 2q` for `q ≥ 1`. Packaged as
`one_div_abs_sin_le_of_two_div (u c) (hc1 : 1 ≤ c)`, which needs no side
condition on `u`.

## Five-primes Child 2: the summit gap ANALYSED AND RESOLVED (mechanism found)

Earlier in the session I had concluded (in `REMAINING.md`) that the parent
`theorem51_typeI_block_summation` was "unprovable / over-strong" because the
envelope seemed to overshoot the platform's first term by a factor of `q`.
**That conclusion was wrong**, and the error is worth recording.

### The mistake

I had been evaluating the envelope at points outside the admissible region:
`x = 10¹²` with `UV = 1600` while the theorem only requires `UV ≤ x/4` — which
is *satisfied*, but at such an `x` the phase `sin(π·d/(2q))` is generic over the
short `d`-range, so the `B`-alternative dominates and the sum is tiny. The
"large ratio" came from dividing that tiny sum by a target scaled by the
inadmissible `x`/`q`. Lesson: **always sweep the whole admissible region
(`U,V ≥ 40`, `UV ≤ x/4`) before concluding a bound is too strong.**

### The correct mechanism (Tao's, now identified)

With `A_d = (1/2)(x/d)log x + C`, `B_d = C/|sin(π·2α·d)|`, `C = 4(log2)log 2x`,
and `X_j = (1/2)(x/L_j)log x` at the block's left endpoint `L_j = 2jq + q/2`:

1. `min (X_j + C) B_d ≤ min X_j B_d + C` — `min_add_const_le`. So the block's
   envelope sum is `(Cor 3.5 at A = X_j) + (#odd d)·C`.
2. **Cor 3.5 at `A = X_j` on a width-`2q` block gives `2X_j + (2/π)Cq log 4q`.**
   The published count `⌊2q/(2q)⌋ + 1 = 2` is off by one: only `q` odd `d` lie
   in the block, i.e. the reindexed range (in `m = (d−1)/2`) is a *single*
   `q`-block, so the sharp count is **1**. This is exactly what makes Tao's
   display carry `2A = 2X_j` and therefore a single `X_j` per block.
3. `#odd d ∈ block ≤ q/2 + 1`, so the `C`-budget `(q/2+1)C ≤ qC + 2C` is
   absorbed by Cor 3.5's `+4q` slack.

Numerically verified: count-1 form `2X_j + (2/π)Cq log 4q` holds on every block
for `q ∈ {4,10,100}` with `max(s/rhs) = 0.60…0.76`; and the maximum of
`envelope / platform-RHS` over the admissible region is **0.44**.
